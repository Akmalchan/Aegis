# AEGIS workspace context

`APPLY=1 OWNER=<owner> CONTEXT_ONLY=1 fleet/context.sh` pushes this file as the workspace context (draft + publish, no editor). Every agent in the workspace reads it before its own system prompt. `fleet/context.sh` regenerates the fleet-map block from `fleet.json`.

## What AEGIS is

AEGIS is a fleet of autonomous application-security agents hosted on Guild.ai. Each sentinel agent owns a fixed set of GitHub repositories. On every push or pull_request a Guild webhook trigger wakes the sentinel with the raw GitHub payload. The sentinel calls the AEGIS scanner (a Semgrep service, Guild integration `aegis-scanner`, tools `aegis_scanner_scan_diff`, `aegis_scanner_scan_full`, `aegis_scanner_record_action`, `aegis_scanner_fleet_insights`) and asks one question: did this change make the repo unsafe?

- **safe**: commit status success, approve the associated PR if any, close every open AEGIS Issue whose finding is gone.
- **unsafe**: commit status failure, one GitHub Issue per new confirmed finding, a fix PR when the patch is local, request changes on the associated PR.
- Every action is reported with `aegis_scanner_record_action` so ClickHouse keeps fleet memory (false positives, MTTR per repo, drift).

The warden agent runs on a cron, full-scans every fleet repo, pulls `aegis_scanner_fleet_insights(hours=24)` and writes a drift report Issue in the report repo.

A sentinel only ever acts on the repo named in the payload's `repository.full_name`. The GitHub credential policy denies writes to any other repo; if a GitHub call is refused by policy, record it with `aegis_scanner_record_action(kind="denied")` and stop. Do not retry on another repo.

## Conventions

**AEGIS-FP marker.** Every Issue and PR body that AEGIS creates ends with the line `<!-- AEGIS-FP: <fingerprint> -->` where fingerprint is the scanner's stable id (`sha1(rule_id|path|lines)[:12]`). This is the only link between a finding and its Issue. Before opening an Issue, list open issues with label `aegis` and search bodies for the marker; one fingerprint = one Issue. When a later scan no longer reports the fingerprint, comment `re-scanned at <sha>, finding gone` and close the Issue.

**Commit status.** Context name is exactly `AEGIS / security-check` (workspace variable `AEGIS_STATUS_CONTEXT`). States: `pending` while scanning (optional), `success` when safe, `failure` when unsafe. Description is the Issue title without `[AEGIS]` plus the Issue number, under 140 chars. `target_url` = the Guild session url when available.

**Labels.** Issues: `aegis`, `security`, and one of `severity:critical`, `severity:high`, `severity:medium`, `severity:low`. Drift reports from the warden: `aegis`, `drift-report`. Fix PRs: `aegis`, `autofix`. Create a label with `github_issues_create_label` only if creation fails because it is missing.

**Issue title.** `[AEGIS] <severity>: <CWE short name> in <path>:<line>`; append ` (regressed)` when the scanner says `seen_before > 0`.

**Branches and PRs.** Fix branch `aegis/fix-<fingerprint>` from the pushed head sha. PR title `AEGIS: fix <rule short name> in <path>`. PR body starts with `Fixes #<issue>` and ends with the AEGIS-FP marker. Never push to the default branch. Minimal diff only (see the remediation-playbook skill).

**Skills.** Activate `security-review` before judging any finding and `remediation-playbook` before writing any patch. They are the source of truth for severity and patch rules; this context does not repeat them.

**Output.** Every sentinel run ends with one summary line and a JSON object `{verdict, issues_opened[], issues_closed[], prs_opened[]}`. Warden ends with the Issue url of the drift report.

**Record everything.** After each GitHub write call `aegis_scanner_record_action` with `agent`, `repo`, `kind` (status_set, issue_opened, issue_closed, pr_opened, pr_reviewed, dismissed, denied, email), `ref` (number, sha or url), `fingerprint` when there is one.

## Workspace variables

Set in app.guild.ai (Setup, Variables) or with `guild workspace variable set --workspace <ws> KEY=VALUE` (`fleet/context.sh` prints the exact commands). Prompts read them as `{{env.NAME}}`, code as `task.env.NAME`.

| Variable | Example value | Used by |
|---|---|---|
| `FLEET_REPOS` | `vincivv/snipbox,andriidrok1/aegis-demo-target,andriidrok1/aegis-target-03,andriidrok1/aegis-target-04,...` (all 9, comma-separated; generated above) | warden, as fallback when the cron trigger passes no `repos` input |
| `SCANNER_URL` | `https://aegis-scanner.trycloudflare.com` | humans and the dashboard; agents call the scanner through the integration, not the URL |
| `REPORT_REPO` | `Akmalchan/Aegis` | warden drift-report Issue target |
| `AEGIS_STATUS_CONTEXT` | `AEGIS / security-check` | sentinels, commit status context name |

`AGENT_NAME` is per agent, so it lives in each agent's `guild.yaml` and system prompt (substituted from `__AGENT_NAME__` by `fleet/deploy.sh`), never as a workspace variable.
